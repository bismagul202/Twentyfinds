# TWENTYFINDS CMS roadmap

Each phase is an independently reviewable release. Apply migrations only in a later authorized implementation phase. The proposed schema below is additive and subject to design review after inspecting the relevant existing columns, indexes and records.

| Phase | Deliverable and acceptance check | Proposed additive database work |
|---|---|---|
| 1. Permissions and audit | Introduce Laravel policies for CMS actions, preserve owner access, and reject unauthorized direct requests. Record edits and publishing in audit history. | Reuse `roles`, `permissions`, their pivots and `activity_logs`. Add missing permission assignments idempotently. Extend log indexes or actor/context fields only where needed. |
| 2. Page lifecycle | Expose built-in pages individually. Add duplicate, eligible soft delete, independent drafts, signed preview, scheduling and revision restore. A new draft leaves the current public page intact. | Reuse `pages`; add immutable `page_revisions`, nullable draft/published revision references, and a separate scheduled revision/time with an index. Preserve `published_at`, slugs, SEO and existing soft deletes. |
| 3. Section builder | Release a small editor for hero, banner, image/text, rich text and CTA first. Add catalog sections, then FAQ/testimonials/reviews/forms/video/gallery and spacing primitives in separate releases. Test duplicate, reorder, disabled sections and responsive rendering. | Add revision-scoped `page_sections` with stable IDs, typed and versioned JSON settings, order, visibility and indexes. Keep a fixed template mapping for secured routes. Reuse catalog records for selections. |
| 4. Media library | Upload and reuse images, add video, then folders, search and replacements. Verify that active and restorable revision references prevent deletion. | Add `media_folders`, `media_assets`, `media_usages` and optional asset versions. Add nullable media references to existing product images, categories and banners. Keep current paths as fallbacks during backfill. |
| 5. Global site and dashboard UX | Add managed site settings and navigation. Upgrade the dashboard shell and reusable table, form, search and bulk-action patterns without breaking existing URLs. | Add typed `site_settings`, `navigation_menus` and hierarchical `navigation_items`. Reuse notifications and existing copy keys. Migrate logo, footer and banner slots incrementally. |
| 6. SEO and storefront delivery | Add metadata, canonical/OG, structured data, robots, sitemap and checked redirects. Cut over route by route to published APIs and cache tags, including invalidation at scheduled publish time. Verify content parity and preview isolation. | Add nullable SEO fields to pages, products and categories plus a unique-source `url_redirects` table. Reuse existing metadata and media references. Revalidate by changed record and dependent listing/tag. |
| 7. Catalog, promotions and inbound stock | Add attribute and collection management first, then supplier and bulk-receiving workflows. Preserve price constraints and verify a receive operation records each stock movement once. | Add attribute definitions/options, collection membership/rules, suppliers, bulk inbound shipments and line items. Reuse product variants, inventory and inventory transactions. Link purchase/landed costs to receipts without exposing them publicly. |
| 8. Customer shopping and order lifecycle | Add customer sessions and persistent cart/wishlist first. Follow with order placement and stock reservations, then restricted UK fulfilment, courier/payment adapters, COD reconciliation and returns. Verify concurrent orders, retries, role restrictions and provider event idempotency. | Reuse users, addresses, carts, wishlists, orders, payments, shipments, returns and refunds. Add stock reservations, provider event IDs, order status/assignment history and COD reconciliation records where the existing schema lacks them. |
| 9. Reviews | Enable customer submission, verified purchase, moderation queue, attachments, replies and abuse reports. Verify that rejected reviews stay private and customer ratings cannot be edited by staff. | Extend `product_reviews` with a nullable verified order-item reference. Add review media links, replies, reports and moderation history, reusing media and audit infrastructure. |
| 10. Forms and marketing | Release real contact and newsletter capture first. Add configurable fields, exports and notifications, then campaigns, consent, analytics and abandoned-cart events. Verify server validation, export access and consent gating. | Add forms, form fields, submissions and campaign/consent records. Reuse newsletter subscribers, banners, coupons and collections. Store provider configuration and secrets separately. |
| 11. Business reporting | Deliver stock and sales reports first, then expenses, landed cost, GBP/PKR reporting and profit and loss. Reconcile reports with recorded order, refund, fee, expense and exchange-rate data. | Add expenses, expense categories, recorded exchange rates and any required cost allocations. Reuse supplier, inbound shipment, order and refund data. Preserve original amounts and rates for historical reporting. |

## Record-preserving rollout

- Before each later migration, back up the database and test a copy with representative records. Compare row counts, references, pricing constraints and existing public API responses.
- Add nullable columns, new tables and indexes first. Backfill in idempotent batches while existing readers continue to work. Verify values before tightening constraints or changing reads.
- Seed initial page revisions and settings from existing records, then fill missing defaults. Keep existing IDs, slugs, media paths, users, product relationships and stock/order history. Redirect changed public slugs.
- Switch one route or module at a time after checking ownership, draft isolation, mobile layouts and existing browsing flows. Retain the previous read path during verification so a rollback can switch traffic back without reversing a data migration.
