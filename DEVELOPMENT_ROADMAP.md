# TWENTYFINDS development roadmap

Implement one task per change. Dependencies are listed by ID. Schema entries are proposals, subject to inspecting existing columns and constraints before implementation. See [PROJECT_VISION.md](PROJECT_VISION.md) and [CMS_ROADMAP.md](CMS_ROADMAP.md).

| Task | Depends on | Acceptance criteria | Proposed database change |
|---|---|---|---|
| 01. Page write authorization | Existing owner gate | Owner can save a page through the existing editor. Guests and unauthorized roles cannot write. The same Laravel policy protects the eventual API. | Reuse roles, permissions and pivots. Seed narrowly scoped page permissions idempotently if needed. |
| 02. Page save audit | 01 | Successful saves log actor, page, action and safe changed fields. Failed saves leave no success event. | Reuse activity logs. Add indexes only if needed. |
| 03. Page draft storage | 01–02 | Save a new draft for one existing page and verify its current public version, ID and slug stay intact. | Add immutable page revisions and nullable draft/published revision references. Backfill existing records. |
| 04. Protected draft preview | 03 | Owner can preview the selected draft. Anonymous and expired requests are denied. Public API and indexing continue to use the published revision. | Reuse revisions and signed short-lived access. |
| 05. Publish and restore | 03–04 | Publish atomically and restore a prior revision as a new revision. Public content changes without rebuilding. | Reuse revision references. Add scheduled revision/time and index in a separate follow-up. |
| 06. One typed homepage section | 05 | Admin edits the existing hero through validated settings and previews/publishes it. Desktop/mobile appearance and fallback remain equivalent. | Add revision-scoped page sections with stable IDs and typed/versioned JSON. |
| 07. Section ordering and toggles | 06 | Drag/drop or keyboard controls reorder sections. Duplicating, disabling and removing sections only affects a draft until publish. | Reuse section order and visibility fields. |
| 08. Extend section types | 07 | Deliver one renderer at a time for banners, sliders, text/media, product/category collections, FAQs, gallery/video, CTA and forms. Validate settings and selections. | Reuse sections, catalog references and media references. |
| 09. Media library | 01 | Upload validated assets, search/select them and record usage. Block deletion while published or restorable content references the asset. Start with images, then add video/folders. | Add media assets and usage references. Add folders when implemented. Retain existing image paths during backfill. |
| 10. Global CMS settings | 06, 09 | Start with logo and announcement, then navigation/footer, typography, colours, buttons, spacing and motion as separate changes. Owner can validate and publish values without changing code. | Add typed settings and navigation menu/items. Reuse existing copy and media. |
| 11. SEO and content delivery | 05 | Publish canonical/OG/robots settings, sitemap and safe redirects incrementally. Test content parity and cache refresh on publish. | Add nullable SEO fields and unique redirect sources. Preserve existing slugs and metadata. |
| 12. Admin table and API pattern | 01–02 | First migrate one editor to authenticated Laravel REST writes. Preserve existing session and URL flow. Add shared search/sort, states and confirmations. Extend to other modules independently. | Reuse existing records and permission/audit infrastructure. |
| 13. Dashboard upgrades | 12 | Add shared search, drawers, media dialogs, bulk actions, theme toggle and one database-backed chart as separately reviewable changes. Empty states show real absence of data. | Reuse persisted data; add a scoped preference only if required. |
| 14. Product attributes and collections | 12 | Begin with attributes for an existing product, then link tags and managed collections. Storefront reflects published choices and keeps price bounds. | Add attribute/options and tag/collection membership, reusing current products and variants. |
| 15. Public stock availability | 12 | Expose availability for active variants from UK inventory. Customer payload contains no costs. | Reuse inventory and movements. Add a lookup index if needed. |
| 16. Persistent guest cart | 15 | Add, update and remove items across refreshes. Laravel validates prices, quantities and availability. A visitor cannot access another cart. | Reuse carts and cart items. Add guest identifier or expiry constraints only if absent. |
| 17. Customer sessions and wishlist | 16 | Add account sign-in first, then cart merge and persisted wishlists in separate changes. Verify ownership on every read and write. | Reuse users, addresses, carts, wishlists and session infrastructure. |
| 18. Order placement and reservations | 15–17 | Server creates an order snapshot with authoritative totals and reserves stock atomically. Retrying cannot duplicate orders or oversell. | Reuse orders, items and inventory; add reservation and idempotency state as needed. |
| 19. UK fulfilment | 01, 18 | Start with assigned order view, then picking/packing, dispatch and tracking, then physical returns and stock discrepancies. Staff cannot access finance or settings. | Reuse shipments, returns and inventory movements. Add history/assignment fields where absent. |
| 20. Payment, COD and courier adapters | 18–19 | Add one approved integration at a time. Verify provider events, duplicate handling and reconciliation. COD is available only for eligible delivery services. | Reuse payments, shipments and refunds. Add provider event identifiers and COD reconciliation records where needed. |
| 21. Supplier receiving | 15 | Add supplier records first, then a bulk inbound shipment receive action. A repeated receipt does not double-increment UK stock. | Add suppliers, inbound shipments and lines. Reuse stock movements. |
| 22. Genuine reviews | 18 | Verified customers submit reviews. Staff moderate with reasons and audit history. Customer ratings cannot be edited by staff. | Reuse product reviews. Add verified order reference, attachments, reports and moderation history as needed. |
| 23. Real contact form | 12 | Existing contact form saves valid messages in MySQL. Invalid submissions fail validation and retries respect spam controls. | Add contact submission storage that can be extended to configured forms. |
| 24. Newsletter and marketing | 23 | Store subscriptions with opt-in and deduplication. Add form builder, campaign configuration, analytics, consent and abandoned-cart capture as separate changes. | Reuse newsletter subscribers, coupons and banners. Add form definitions/submission metadata and consent/campaign records where required. |
| 25. GBP/PKR business reporting | 20–21 | Deliver stock and sales reports before costs and P&L. Ledger totals reconcile against sales, landed costs, fees, refunds and recorded exchange rates. | Reuse operational records. Add expenses, exchange rates and cost allocation records if required. |

## Rollout safeguards

Back up and test on copies before later schema work. Use additive tables/nullable fields, idempotent backfills, and compatibility reads until validation passes. Preserve existing IDs, slugs, product data, upload paths, text overrides, users and order/stock history. Move only the feature authorized for each phase. Test permission denials and draft isolation before switching public reads.

**Recommended next task:** 01. Add page-write authorization as a small change with no storefront redesign. It protects the existing page editor and is the dependency for audit logging, protected drafts and the visual builder.
